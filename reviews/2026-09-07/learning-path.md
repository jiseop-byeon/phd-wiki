# Physical AI 독학 학습경로 정독 감사

- 감사일: 2026-09-07
- 범위: 배정된 학습 진입·깊이·논문 읽기·용어·기록·템플릿 문서 10개
- 상태: **완료** — 10개 파일, 2,435줄을 현재 source에서 끝까지 읽음
- 방법: 과거 대화·과거 평가를 근거로 재사용하지 않고 현재 파일 본문을 순서대로 정독했다. 페이지 수나 노트 수만으로 완전성을 판정하지 않았다. 다른 분야 agent의 범위인 Foundations index Tier/로컬 reference, Radar 본문·compiler/UI, 자동 QA, 렌더 표본은 평가하지 않았다. 사실 오류의 외부 재검증도 이번 범위에는 포함하지 않았다.

## 결론

이 위키는 초보자가 Physical AI 논문의 문제·입출력·주장·증거·한계를 읽는 데 필요한 **좋은 독해 도구**를 이미 갖췄다. 특히 깊이의 두 축을 명시하고, RT-1 한 편에 문장·수식·증거·종료 시험을 실제 적용한 점이 강하다. 현재의 주요 실행 충돌은 (1) 엄격한 목록 순서가 선수지식 순서와 어긋나고, (2) `◐ = 노트 후 원문`인데 노트가 없는 ◐ 항목이 있다는 점이다. 개별 페이지·논문의 종료 시험은 이미 있으므로 학습 과정이 차단된 것은 아니다. 다만 이를 묶어 “공통 문해력 트랙을 마쳤는가”를 한 번에 확인하는 선택적 통합 시험을 두면 종료 판단이 더 쉬워진다는 것은 사실 판정이 아니라 이 감사의 교육 설계 제안이다.

## 발견

### LEARN-001 — P1 — “리스트 순서대로”가 VLA의 선수지식 순서를 깨뜨린다

- 근거: `content/index.md:52`는 “`핵심 논문 리스트를 순서대로`” 읽으라고 한다. 같은 홈의 전문화 경로는 `content/index.md:54`에서 ACT와 Diffusion Policy 전에 “`Transformer와 DDPM을 경로 3에서 먼저 읽어라`”라고 별도 우회 지시를 한다. 하지만 리스트는 `content/01-canonical-papers/canonical-list.md:80`에서 VLA 절을 시작해 `:88`에 Diffusion Policy, `:89`에 ACT, `:93`에 π0를 놓은 뒤, `:108`에서야 Diffusion 절을 시작하고 `:112`에 DDPM, `:119`에 Flow Matching을 둔다.
- 왜 문제인가: 초보자가 홈의 단일 명령을 충실히 따르면 Diffusion Policy를 DDPM보다, π0를 Flow Matching보다 먼저 만난다. 홈의 긴 전문화 문장을 기억한 독자만 예외 처리를 할 수 있어 “처음부터 끝까지” 경로가 자립하지 않는다.
- 구체적 개선: 홈의 문구를 “리스트의 **선수지식 경로**를 따라”로 바꾸고, canonical list의 VLA 절 바로 위에 최소 선행 표를 둔다. 예: `ACT → Transformer`, `Diffusion Policy → DDPM`, `π0 → Transformer + Flow Matching`; 미통과 항목은 링크를 먼저 읽고 돌아오게 한다. 또는 공통 최소 경로에서 Diffusion 핵심(DDPM·Flow Matching)을 VLA보다 앞에 둔다.
- 확신도: 높음(현재 source 내부의 직접 순서 충돌).

### LEARN-002 — P1 — `◐ = 노트 후 원문` 규칙과 “노트 없음” 항목이 모순된다

- 근거: `content/01-canonical-papers/canonical-list.md:23-25`는 ◐를 “`노트 후 원문 훑기`”로 정의한다. 그러나 같은 목록의 `:131-135`, `:141-142`, `:156-157`에는 ◐이면서 명시적으로 “`노트 없음`”인 서베이·고전·촉각 논문들이 있다.
- 왜 문제인가: 독자는 필수 첫 단계인 “노트”를 찾을 수 없다. 이 상태는 단순 링크 누락이 아니라 학습 절차가 실행 불가능한 경우이며, 특히 원문 진입 보조가 필요한 초보자에게 가장 크게 작용한다.
- 구체적 개선: 두 선택 중 하나를 일관되게 적용한다. (A) ◐ 항목에는 최소 노트를 만든다. (B) 노트를 만들지 않을 선택이면 기호를 `◐-원문`처럼 분리하고 “초록→지정 절/그림→결론”의 대체 절차와 해당 개념 페이지의 정확한 절 링크를 붙인다. 현 상태의 `노트 없음` 괄호만으로는 충분하지 않다.
- 확신도: 높음(정의와 항목의 직접 모순).

### LEARN-003 — P2 — 개별 종료 시험을 묶는 선택적 전역 확인이 없다

- 근거: `content/00-study-depth-guide.md:182-186`은 Literacy/Working/Mastery의 주제별 완료 기준을 준다. `content/01-canonical-papers/how-to-read.md:209-217`과 한국어 `:412-422`는 논문 한 편의 5항목 퇴장 시험을 준다. 반면 홈 `content/index.md:51-54`의 경로는 Foundations 통과 후 논문 목록과 전문화 경로로 보내지만, 어느 논문/주제 묶음을 통과하면 위키의 최상위 목표가 끝나는지는 말하지 않는다.
- 왜 개선 가치가 있는가: 기존의 주제별·논문별 시험으로도 학습은 진행하고 완료할 수 있다. 다만 목록이 긴 만큼 독자가 “공통 트랙을 충분히 마쳤는가”를 여러 결과에서 스스로 종합해야 하므로, 희망하는 학습자에게는 통합 확인 장치가 종료 판단 비용을 낮춘다. 이는 학습 차단이나 사실 오류가 아니라 설계상 선택지다.
- 구체적 개선: 홈의 경로 3 뒤에 **선택적 Literacy 통합 확인**을 둔다. 예시 문안: “원하면 처음 보는 논문 3편(인식 1, 로봇학습/VLA 1, 로봇 시스템·건설 1)에 대해 ① 문제·I/O ② 핵심 식/도식 ③ 주장-증거 대응 ④ 한계 ⑤ 계보 위치를 먼저 작성하고 원문과 대조하라. 통과하면 공통 트랙을 닫고 선택 전문화로 간다.” 기존 per-page·paper exit를 대체하거나 필수 관문으로 만들지 않는다.
- 확신도: 높음(전역 통합 단계의 부재는 직접 확인); 우선순위와 개선 방식은 교육 설계 판단.

### LEARN-004 — P2 — 공통 필수와 선택 전문화의 경계가 canonical list 안에서 다시 흐려진다

- 근거: 홈은 `content/index.md:51-54`에서 체계적 독학, 논문 읽기, 조감, 매니퓰레이션 전문화를 구분한다. 그러나 `content/01-canonical-papers/canonical-list.md:11-13`은 전체를 하나의 “reading backbone”이자 “rough reading order”로 부르고, 같은 파일 안에 일반 DL부터 Robotics study guides(`:170-193`), Construction(`:196-240`), Navigation(`:242-283`)까지 이어 놓는다. 각 절에 공통 Literacy 필수인지, 연구방향 선택 확장인지의 종료/분기 표지가 없다.
- 왜 문제인가: ★◐○은 “얼마나 깊게 읽는가”만 말하며 “이 항목을 지금 읽어야 하는가”는 말하지 않는다. 초보자는 매니퓰레이션을 택해도 내비게이션 15편까지 공통 과정인지, 어느 시점에 분기해야 하는지 알기 어렵다.
- 구체적 개선: 목록 맨 위에 `공통 코어 / 시스템 코어 / 선택 전문화(매니퓰레이션·내비게이션·HRI·건설 세부)`의 경로 표를 두고 각 절에 `필수`, `한 갈래 선택`, `참고 확장` 배지를 추가한다. ★◐○은 읽기 분량으로만 유지한다.
- 확신도: 높음(기호가 선택 여부를 표현하지 않는 것은 문서가 직접 명시).

### LEARN-005 — P2 — 과거 일지가 현재 사실·현재 할 일처럼 읽힐 수 있다

- 근거: `content/study-log.md:6-7`은 이 페이지를 과거 학습 일지라고만 설명한다. 하지만 과거 항목 안에는 “`ObjectNav은 경쟁 벤치마크로서 죽었다`”(`:145`), “`Isaac Gym은 지원 종료`”(`:217-218`), “`현재 제한`”(`:817`)처럼 시간에 민감한 현재형 판단이 있고, 더 오래된 끝부분에는 “`다음 읽을 것`”(`:869`, `:874`, `:877`)과 “`남은 큰 덩어리`”(`:893-895`)가 후속 완료 기록과 함께 그대로 남아 있다.
- 왜 문제인가: 날짜 제목은 역사성을 암시하지만 검색·백링크·부분 인용으로 해당 문장만 만난 독자는 이를 현재 상태나 아직 유효한 할 일로 오인할 수 있다. 특히 소프트웨어 지원·벤치마크 존속은 빠르게 변한다.
- 구체적 개선: 상단에 “**역사 기록이며 현재 사실/현재 백로그가 아니다. 각 주장은 해당 날짜 기준이고 최신 상태는 연결된 본문을 확인한다**”는 경고를 추가한다. 각 항목의 `현재/다음/남은 것`은 `당시 상태`로 표현하고, 변동성 높은 주장에는 `기준일: YYYY-MM-DD`와 현재 본문 링크를 붙인다. 현재 할 일은 별도 단일 페이지에서만 관리한다.
- 확신도: 높음(오래된 현재형과 완료 전 할 일이 실제로 공존).

### LEARN-006 — P2 — 읽기 깊이와 사용 깊이가 같은 이름을 공유해 세 체계를 기억해야 한다

- 근거: 깊이 가이드는 `content/00-study-depth-guide.md:14-15`에서 `★◐○ = 논문을 얼마나 읽는가`, `Literacy / Working / Mastery = 지식을 얼마나 잘 사용하는가`로 나눈다. 그런데 how-to-read는 `content/01-canonical-papers/how-to-read.md:20-27`에서 논문 읽기 깊이를 다시 `Recognition / Literacy / Working / Mastery`로 명명하고, `:34-35`에서 같은 단어를 두 축에 재사용한다고 설명한다.
- 왜 문제인가: 설명 자체는 정직하지만 초보자는 기호 축, 논문 읽기 4단계, 주제 사용 3단계의 대응을 계속 번역해야 한다. 특히 “이 논문은 Literacy로 읽었지만 주제는 Working” 같은 진술이 문맥 없이는 모호하다.
- 구체적 개선: 논문 읽기 4단계는 `Pass 0 인지 / Pass 1 요약 / Pass 2 구현 추적 / Pass 3 비판`처럼 별도 이름으로 바꾸거나 ★◐○ 하나로 통합한다. `Literacy/Working/Mastery`는 주제 사용 능력에만 예약한다.
- 확신도: 높음(의도적인 용어 재사용이 source에 명시).

### LEARN-007 — P2 — paper-note 템플릿이 읽기 가이드의 검증·종료 규약을 강제하지 않는다

- 근거: how-to-read는 식별자·원문 주장·판본·1차 색인을 확인하라고 한다(`content/01-canonical-papers/how-to-read.md:180-200`)며, 종료 시험에 I/O·핵심 식/도식·선행/후속·한계를 요구한다(`:209-215`). 반면 `content/templates/paper-note.md:3-10`은 arXiv/PDF/code/project 메타데이터를 두지만 읽은 판본·출판 상태·주장 위치를 기록하는 방법을 안내하지 않으며, 본문 `:22-49`은 요약/배경/방법/결과/한계/연결의 자유 서술이라 I/O와 종료 시험 결과가 빠져도 완성된다.
- 왜 문제인가: 좋은 가이드가 있어도 새 노트의 기본 양식이 이를 기억 장치로 만들지 못한다. 특히 ○ 항목에서는 노트 자체가 학습의 전부이므로 템플릿 누락이 그대로 학습 누락이 된다.
- 구체적 개선: 새 검증일 필드를 만들지 말고 기존 규약의 `last_verified`를 템플릿에서 재사용한다. 식별자는 자료 형식에 따라 `doi`, `arxiv`, `source-url` 중 존재하는 것만 선택하게 하며 DOI나 arXiv를 모든 자료에 강제하지 않는다. 필요한 경우 `version-read`와 `publication-status`를 선택 필드로 두고, 본문에는 `Method I/O`, `핵심 주장 ↔ 근거(표/그림/쪽)`, `train vs inference`, `predecessor/successor`, `exit test`를 추가한다. 결과 수치에는 원문 위치와 조건을 같이 적는 예시 한 줄을 넣는다.
- 확신도: 높음(가이드의 필수 질문과 템플릿 필드 직접 비교).

### LEARN-008 — P2 — concept-note 템플릿이 자체 Literacy 계약보다 얕다

### LEARN-009 — P2 — 영한 병기에서 중요한 범위·용례 단서가 한국어에 빠진다

- 근거: 용어집은 `content/glossary.md:9-11`에서 각 항목을 “English · 한국어”로 쓴다고 선언한다. 그러나 `:26`의 영어는 IL이 BC·DAgger·IRL을 포괄한다고 설명하는 반면 한국어는 “BC는 IL의 부분집합; offline RL…”만 남겨 IL의 범위를 생략한다. `:38`도 영어에는 post-training의 “recent usage”와 π0에서의 구체적 의미가 있으나 한국어는 “정렬 단계 전체”로만 끝난다.
- 왜 문제인가: 한국어만 읽는 초보자는 바로 이 항목들의 핵심인 용어 경계와 논문별 용례 차이를 잃는다. 번역이 요약이어도 학습 판단을 바꾸는 단서는 보존돼야 한다.
- 구체적 개선: 번역 분량의 완전한 대칭보다 **판별 정보 대칭**을 규칙으로 둔다. 예: line 26 한국어를 “BC는 IL의 부분집합(IL에는 DAgger·IRL도 포함); offline RL은…”으로, line 38은 “최근 용례로 SFT+RLHF 전체; π0에서는 고품질 과제 데이터 단계”까지 보강한다.
- 확신도: 높음(같은 줄의 영문·국문 정보 직접 비교).

### LEARN-010 — P3 — 용어집 중복 표제가 단일 조회 결과를 깨뜨린다

- 근거: `content/glossary.md:61-62`에 `Adapter`가 연속 두 번, `:71-72`에 `Autoregressive`가 연속 두 번 정의된다. Adapter 두 설명은 하나는 LoRA를 “most common form”, 다른 하나는 이전 adapter와 구별되는 변형으로 설명해 미묘하게 다른 분류를 준다.
- 왜 문제인가: 조회 사전에서 같은 표제가 둘이면 어느 정의가 정본인지 알 수 없고, 서로 다른 adapter 계열과 LoRA의 관계를 초보자가 잘못 합칠 수 있다.
- 구체적 개선: 각 쌍을 하나로 병합한다. Adapter는 “고전 bottleneck adapter”와 “LoRA식 저랭크 update”를 하위 문장으로 구분하고, Autoregressive는 정의+지연 함의를 한 항목에 합친다.
- 확신도: 높음(동일 표제 중복 직접 확인).

### LEARN-011 — P3 — canonical list의 체크박스는 학습자 완료 표시처럼 보이지만 실제로는 노트 존재 표시다

## 현재 강점

- `content/index.md:44-46`이 목표를 “균일한 숙달”이 아닌 논문의 용어·수식·주장·실험 표현을 읽는 연구 문해력으로 제한해 과잉 학습을 막는다.
- `content/00-study-depth-guide.md:215-228`은 권장 깊이와 페이지 자체 지원 깊이를 분리해 “페이지 하나로 Working이 된다”는 과장을 피한다.
- `content/01-canonical-papers/how-to-read.md:305-359`의 RT-1 시범은 문장→수식→증거→종료 시험을 한 번에 보여 주며, 초보자가 추상 체크리스트를 실제 산출물로 바꾸게 한다.
- `content/glossary.md:13-55`의 혼동 쌍은 단순 정의보다 연구 독해에 유용하다. policy/controller, objective/metric, state/observation/estimate/belief 같은 경계를 바로 비교한다.
- `content/00-study-depth-guide.md:300-319`는 매니퓰레이션 Mastery 영역을 실제 페이지에 매핑하고, 없는 전용 페이지도 숨기지 않는다.
- `content/study-log.md`는 날짜별로 판단 변경과 오류 수정 근거를 남겨 지식이 어떻게 교정됐는지 추적할 수 있다. 문제는 기록의 존재가 아니라 현재 안내와의 경계 표시다.

## “누락”이 아니라 선택 확장인 것

- **모방학습 전용 페이지 부재**: `content/00-study-depth-guide.md:309-312`가 RL 기초·ACT/Diffusion Policy·원격조작 페이지에 나뉜 의도적 구조라고 밝힌다. 전용 페이지 신설은 필수 누락 보완이 아니라 탐색 비용이 실제로 높다는 증거가 생길 때 선택할 확장이다.
- **모든 인접 분야의 Working/Mastery**: `content/00-study-depth-guide.md:210-213`이 기여 페이지와 가장 가까운 의존 페이지만 Mastery로 올리라고 한다. 광범위한 수식 유도·구현·재현을 공통 코어에 추가하는 것은 목표가 아니다.
- **모든 논문의 상세 노트**: ○ 논문은 계보 이해용이라는 설계 자체는 타당하다. 다만 LEARN-002처럼 ◐로 지정한 항목의 절차만 실행 가능하게 맞춰야 한다.
- **Radar·추가 최신 논문·더 많은 페이지**: 문해력 종료 조건이 먼저다. 페이지나 논문 수의 증가는 현재 감사에서 완전성의 증거도, 필수 개선도 아니다.
